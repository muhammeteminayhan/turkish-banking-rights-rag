## Findings

1. **PostgreSQL full-text search is the weak leg.**
   - `ts_rank` has no IDF: a chunk that repeats common stems (`sayıl`, `kan`, `yönetmelik`,
     `banka`, `madde` — each in 790–1,570 of the 2,692 chunks) outranks the one that
     contains the rare, telling word. For 32 of 56 questions no chunk of the expected
     article is in FTS's top 10.
   - The Snowball Turkish stemmer is inconsistent: "kartı" → `kar`, "kartının" → `kartı`,
     "kartları" → `kart`; "Kanun" → `kan` but "Kanunun" → `kanu`. PostgreSQL and the
     `bm25` row use the same algorithm.
   - In RRF, FTS pulls the hybrid **below vector search alone** (R@5 0.679 vs 0.821).
     The reranker repairs most of it (`full` 0.893).
2. **BM25 with prefix-5 stems is the better lexical leg** in every comparison: alone
   (0.696 vs 0.304), fused (0.759 vs 0.679), and after reranking (R@10 0.973 vs 0.938).
   This is the plan's ablation row; the plan's production choice was PG FTS (see
   *Decisions needed*).
3. **The reranker adds the most:** +0.20 R@5 over plain fusion with FTS, +0.15 with BM25,
   for about 260–290 ms per query on the GPU.
4. **Direct citations** matter where the search alone fails: on the 6 questions that cite
   an article, `hybrid_rerank` scores 0.833 and `full` 1.000. The citation rescues b1-001
   ("6502 sayılı Kanunun 22. maddesi"), where FTS ranks the 6502 annex tables first.
5. **Remaining misses of `full`** (8 questions whose expected articles are not all in the
   top 5 chunks), for example:
   - the "hesap işletim ücreti" rule (b1-015) loses to payment-service articles;
   - the unfair-terms annex list (b1-020);
   - the payment-services source of the three-source stolen-card question (b1-023);
   - "10 yıl kullanmazsam devlete geçer mi" (b1-062) finds payment-service articles
     instead of the dormant-account rule.

   One is a golden-set question rather than a search miss: b1-028 retrieves 6502 m.70,
   which states the same rule as the expected Hakem Heyetleri Yönetmeliği articles in
   slightly different words, so the program did not list it as an equivalent. These are
   good M4/M5 error-analysis cases.

## Issues found and how they were handled

1. **A test destroyed the real index.** The first integration tests built into a temporary
   schema with `search_path = test, public`. `DROP TABLE IF EXISTS chunks` found no table
   in the empty test schema and dropped `public.chunks`. The real index was rebuilt
   (13 s). Fixes: the DROP is qualified with `current_schema()`; the `--schema` option was
   removed; integration tests use their own database `finhak_test`. A regression test
   builds into a second schema and checks the first index survives.
2. **3 s per connection.** `localhost` resolved to `::1` first while Docker listens on IPv4
   only. The default URL and `.env.example` now use `127.0.0.1` (integration tests 62 s →
   3 s).
3. **The Tebliğ and the Talimat disagree on one sentence.** The Talimat (13.01.2026) s.4(a)
   requires separate consent for fee increases above CPI; the consolidated Tebliğ m.7/1
   on mevzuat.gov.tr does not contain that sentence. I checked the raw HTML: it is not a
   parsing loss. Question b1-026 is marked for your check.
4. **Port 5432 is taken** by another project's container (`omnivision_db`); this project
   uses 5433.
5. **Stemmer limits.** prefix-5: words shorter than five letters plus a suffix miss their
   stem ("faizler" → `faizl`, "faiz" → `faiz`), documented in a test. Snowball BM25 takes
   7.7 s to build (stemming every word); prefix-5 0.4 s.

## Code review

Two ECC reviewers read the code before the commit: `ecc:python-reviewer` and
`ecc:database-reviewer`. Neither found a CRITICAL issue. The database reviewer found no
SQL or tsquery injection: it ran every code point that passes the sanitiser, plus 20,000
random hostile strings, through the full query. Fixed, test first:

| Finding | Fix |
|---|---|
| HIGH: overlapping equivalence groups scored differently depending on which copy was found (b1-023: 0.667 vs 0.333) | Groups that share a chunk are merged (transitively); tested both ways |
| HIGH: "Madde R@k" de-duplicated articles before cutting at k, so a hit at chunk rank 10 counted for R@5 | Article hits are now counted within the top-k **chunks**, what generation reads. The table above was re-run with this definition |
| MEDIUM: false direct citations ("ödeme talimatımı … 3. maddesine", "6698 liralık", "sözleşmemin 7. maddesi …, Tüketici Kanunu"), and "5. madde 100 TL" read as article 100 | The document must be named right before the article; no bare "talimat"; amounts excluded; the ordinal form wins overlaps; "22 ila 24" and "22-24" expand |
| MEDIUM: one long cited article filled all result slots; 200 citations in one question meant 200 queries | At most 3 chunks per cited article (best by reranker), cited articles take turns, at most 5 citations looked up |
| MEDIUM: results of a same-day re-run overwrote the full ablation | Result folders carry the time |
| MEDIUM: the 6 citing questions are partly a lookup for `full` | The report shows citing vs. other questions separately |
| MEDIUM: unbounded FTS question (100,000 words → error) | Cut at 2,000 characters |
| LOW: model or database errors gave tracebacks; `--limit` unchecked | Clear errors and exit 1; `--limit` 1..50 |
| LOW: `to_tsquery` re-parsed hyphenated lexemes ("e-pos") into phrases | The lexemes are cast to `tsquery` directly |
| LOW: `CREATE EXTENSION` on every connection (fails for a read-only role) | Only the index builder creates it |
| LOW: a rebuild could wait forever on a lock; two builds could race | `lock_timeout` 15 s and an advisory lock |

Left open, documented:
- **The HNSW index is not used.** At 2,692 rows PostgreSQL prefers a sequential scan,
  so vector search is exact. This is fine for evaluation; the index will matter once the
  corpus grows.
- **The app connects as the database superuser** (local Docker only). M6 adds an
  application role.
- **A bare second article number** ("madde 22 ve 23") is not taken as a citation,
  because it cannot be told from an amount or a day count.
